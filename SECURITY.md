# Security

Report vulnerabilities privately through the repository's
[security advisory form](https://github.com/seankoji-com/t3-plugins/security/advisories/new).
If private reporting is unavailable, use the contact route in the
[organization security policy](https://github.com/seankoji-com/.github/blob/main/SECURITY.md).
Do not put exploit details, secrets, or private logs in a public issue.

Include the affected revision, a minimal reproduction with synthetic data, and the
boundary crossed. Relevant boundaries include manifest/path ownership, unintended
file access, provider delegation, settings writes, and local-to-cloud data transfer.

Only the latest release receives fixes. This early project has no response-time SLA.
Workflow instructions are not a security sandbox. Provider permissions and host
isolation remain responsible for enforcing access.
