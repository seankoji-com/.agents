# Configuration, design and written-strategy review

Public admission also verifies `upfront-agreement.md`. Nested operations must be included in the same agreed scope. Reuse the existing binding on continuation; no retain-or-stop applies to unchanged agreement-bound runs.

Apply `model-selection.md` first. Before substantive investigation, drafting or
children, collect work/review choices together. Explicit choices count. Only
operation/capability/identity/resume preflight precedes answers. A raw factual or
format check that later needs synthesis/delegation stops there for choices.

The public helper is `python3 PKG/scripts/plan_review.py ACTION --input FILE`.
It stores no model defaults, launches no tasks and accepts no review itself.

- `admit`: operation, request_reference, output_name, invocation_id, selection and
  independently retained selection_sha256. Direct helper categories return without
  choices or children. Qualifying commands seal an admission descriptor.
- `continue`: admission, invocation_id, event (wake/repair/compaction/resume), and
  retain for pinned Ralph resume. `forward: true` consumes an alias once. A new
  invocation cannot reuse another answer. Scheduled reuse additionally requires
  schedule_id, fresh capabilities and current policy_digests; no schedule is created.
- `dispatch`: admission plus shared role/slot_id, exact optional target/options,
  data_classes and recorded unavailable/live_tasks. It returns exact arguments;
  host tools own execution. Work replacement/direct fallback needs its own authority.
- `prepare`: descriptor, inputs, metadata_file. The descriptor contains admission,
  kind, document `{path,sha256,bytes}` and exact requirements. Inputs contain verbatim
  requests/decisions with real references and contiguous clause mappings,
  requirements, repository_root, evidence_paths and optional attachments,
  declared_paths/load_bearing_decisions. Record actual document authors first.
- `attach`: descriptor, metadata_file, receipt (actual shared receipt file).
- `publish`: descriptor/output_file atomically publishes validated evidence to a
  declared private locator; it grants no task scope or action authority.
- `validate`: descriptor with the returned metadata pin as `planning_review`.
  This dereferences persistent subject, separate pinned job, request, source,
  producing selection, actual host identities, rubric and complete assessments.
  Never replace it with a boolean, prompt, text assertion or provenance check.

Use the returned snapshot to create a **separate** manifest-pinned planning job
through `PKG/shared/planning_review_cli.py`, following `planning-review.md`.
Metadata references its private stable subject record. Replacements/resumes retain
rounds and objections. Fresh repaired content needs another counted assessment.
Empty findings and no-change conclusions still need coverage. Rejected majors
retain the original-lineage/owner-resolution rule; adverse is not unavailable.

Configuration kinds: `conclusions`, `proposal`, `bootstrap`. Each descriptor carries
`observation_conclusions: {findings: [...], changes: [...]}`, including empty lists.
These conclusions enter the reviewed snapshot. Audit validation and parent acceptance
refuse different published lists; changing conclusions reopens review.
A proposal also pins
plan_file, plan_digest and an immutable before_file matching the plan's before hash.
The helper binds before/candidate/plan bytes as `private-settings`. Specific sharing
authority is required even for a selected reviewer; never send raw private data to
another provider first. Snapshot the before bytes outside every checkout and worker
scope. Include source-specific access/precedence, parse/load/enforcement, rollback,
conflict and backup criteria. No-change conclusions still review.

`approve` takes descriptor and owner `{path, source:{reference,answer,sha256},
plan_digest}` **after** review. It returns the content-bound concrete approval.
`apply` collects its own choices but adds no duplicate planning assessment for the
unchanged proposal. Pass `{admission, approval}` with `align.py apply --context FILE`.
Any candidate/digest change reopens review and owner approval. Approval and review
never widen settings authority. Apply observations include `apply_context` and
`applied_plan`; backup, parse, provider load, required enforcement and rollback rules
remain mandatory. A pre-execution review remains checkable through immutable before
bytes after the authorised target replacement.

Elephant's `design` descriptor additionally names job_file and factual_stage.
Accept repaired facts first. Refuted/unknown claims cannot enter plan review. Declare a private
`resources.adopter_design_file` locator in the initial cold-read stage and use
`publish` with descriptor/output_file after review. Repairs replace this validated
evidence without repeating owner scope approval. An inline `resources.adopter_design`
descriptor is also supported through an owner-bound plan revision. Cold preparation and acceptance validate it before the
fresh document-only reader runs. Facts, design adequacy and readability are three
separate gates; no fallback relaxes factual/cold-read author independence.

Ralph/babysitter kind `strategy` applies only when an actual written strategy exists.
Do not invent an artifact or evaluator for ordinary loops. Store babysitter strategy
in stage `resources.adopter_strategy`; public prepare/direct/acceptance checks it.
Ralph CLI init takes `admission`; `strategy` attaches a reviewed descriptor while
quiescent. Unchanged agreement-bound `resume` reuses the saved admission without
retain-or-stop. Status/stop stay direct. Legacy checkpoints remain pinned to their
original package and cannot gain new endpoint/fallback authority by resuming.
Blocking-feedback repair, final full evaluation,
recovery and lineage rules remain stronger than planning fallback. Babysitter keeps
merge authority, requested final-head review and the coordinator's sole native watch.

Integrated tuneup observations include `adopter_output`; job acceptance checks that
it belongs to the producing admission. Raw diagnostics/intermediate source checks
remain direct. Domain rubrics live in `references/adopter-review-rubric.md`.

Report requested outcome, actual mode/model/options, substituted/unavailable slots,
reviewed content, changes from feedback, every disposition, rounds and remaining
blockers with owner/next action. Separate source review, owner approval, local checks,
provider observations and execution authority. These are locally transcribed facts,
not cryptographic remote proof. Fixtures establish enforcement, not model adherence.
