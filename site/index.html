From install to first run in a minute

A skill is a short guide your agent reads when it does a particular kind of work. Nothing runs in the background and there is no account to make.

  1. Install a skill

    From your project folder, run npx skills add seankoji-com/.agents --skill think. The installer asks which agents to add it to. It needs Node.js 22.20 or later.

  2. Ask for the job

    Name the skill in a normal request, such as Use think on this plan before we build it, or use a slash command like /think where your agent supports them.

  3. Get the result and its evidence

    Your agent follows the skill's steps and tells you what it decided, what it checked and what still needs you.

Made for T3 Code

The skills are written and tested in T3 Code, which runs agents from several providers, such as Codex, Claude and OpenCode, in one app. That lets the skills do things a single agent can't do on its own.

A second opinion from another model

A model checking its own work tends to share the blind spots that produced it. review, think and challenge ask a model from a different family instead, and T3 can start one on another provider without leaving the conversation. Why this matters.

Why another model family checks the work

A model reviewing its own work, or a close relative's, tends to rate it too kindly and to repeat its mistakes. Research on AI judges points the same way.

  • Models favour their own writing. GPT-4 and Llama 2 can recognise their own text, and the better they recognise it, the more they prefer it (Panickssery, Bowman and Feng, 2024). GPT-4 shows significant self-preference, linked to how familiar the text looks to it (Wataoka, Takahashi and Ri, 2024).

  • Related models make the same mistakes. When two models are both wrong, they pick the same wrong answer 60% of the time on one leaderboard dataset. A shared provider or architecture makes this more likely (Kim et al., ICML 2025).

  • Checking yourself doesn't fix much. Without outside feedback, models struggle to correct their own reasoning and sometimes make it worse (Huang et al., ICLR 2024).

  • Mixed panels judge better. A panel of smaller models from different families beat a single GPT-4 judge on six datasets, with less bias, at over seven times less cost (Verga et al., 2024).

So the skills always ask a model from a different family than the one that did the work, and they want evidence, not just a verdict. If no second family is available, your agent says so instead of reviewing its own work. These studies cover AI judges and reasoning tests, not these skills directly. Read the full rationale.

What you need

T3 Code, or another coding agent

T3 Code gets the most out of these skills. Claude Code, Codex and other agents that support skills can use any skill whose tools they provide. A skill marked "Needs T3 Code" relies on T3's background workers. On T3, also install agent-tuneup. Several skills read its T3 permission check before they start helper sessions.

That check works around a known problem. In T3's Full access mode, Codex rejects any command that one of your Codex rules says to ask about, because Full access turns asking off (T3 Code #12248, tracked upstream in Codex #41068).

Node.js for the installer

The Skills CLI needs Node.js 22.20 or later. The skills themselves are Markdown, plus a few small Python 3.10 helpers.

Your say on what happens

Skills that commit, push or merge stay inside what you asked for. "Review it but don't merge" is a limit the agent keeps.
