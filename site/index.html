What npx skills does

Every Install command runs the Skills CLI, an open-source installer from Vercel Labs for the open Agent Skills format. npx downloads and runs it on the spot, so the only prerequisite is Node.js 22.20 or later.

  1. Fetches the skill

    It downloads the named folder from this GitHub repository: the SKILL.md instructions plus any scripts and references beside them.

  2. Asks which agents you use

    It detects the coding agents on your machine and asks which of them should get the skill.

  3. Puts it where each agent looks

    It keeps one copy and links it into each agent's skills folder, such as .agents/skills/ for Codex and .claude/skills/ for Claude Code. Add -g to install for your user account instead of this project.

Commands you will use

npx skills add seankoji-com/.agents
Pick skills from this library in the terminal.
npx skills add seankoji-com/.agents --skill think -g
Install one skill for every project.
npx skills list
Show what is installed.
npx skills check then npx skills update
Look for newer versions, then install them.
npx skills remove think
Uninstall a skill.

Find skills from other authors at skills.sh, or see this library's page there. The CLI's command reference lists every flag.

Once a skill is installed, ask for the work by name, such as Use think on this plan before we build it, or type /think where your agent supports slash commands. focus-group and binaric never start on their own. You invoke them by name, and other skills can point an agent to binaric when it writes a brief for another agent. To install several skills in one command, tick them in the list above.

What is ~/.agents/skills?

.agents/skills is a folder name that many coding agents share. Codex, OpenCode, Cursor, Gemini CLI, GitHub Copilot and others look for a project's skills in .agents/skills/. Codex also reads ~/.agents/skills/ in your home folder, for personal skills that follow you into every repository. Claude Code reads .claude/skills/ instead, so the Skills CLI links skills there as well.

This library is called .agents for the same reason. Clone it into your home folder and its skills land at ~/.agents/skills, where Codex finds them with no install step. That is how the library's owner runs it. Run git -C ~/.agents pull to update.

If ~/.agents already exists, for example from global Codex installs, clone somewhere else and point your agent's skill discovery at the clone's skills folder.

More detail: where Codex looks for skills, the Skills CLI's folder for each agent, and working from a clone in the README.

Built for T3 Code

T3 Code is an open-source desktop app for coding agents. It runs Codex, Claude Code and OpenCode sessions side by side, and gives agents tools to start other agents, work in separate Git worktrees and watch pull requests. Install it with brew install --cask t3-code or from GitHub.

The skills are written and tested in T3 Code. Each one falls into one of three groups.

Needs T3 Code

implement backlog-burn raise-issue

These hand work to T3 delegates that run in their own threads or worktrees, so your conversation stays free. raise-issue can still file inline if you ask for that explicitly.

Better in T3 Code

review think challenge review-loop hillclimb choose-design focus-group ship babysitter

  • Reviewers, judges and designers start on another provider from the same conversation. Code review needs a second model family; without one, the agent reports the review as unavailable.
  • babysitter uses T3's pull request watch to wake when checks or reviews change. Elsewhere it waits with its bundled pr-wait helper.
  • ship, implement and review-loop show their phases in T3's Tasks row. choose-design shows mockups side by side in preview frames.

Works anywhere

raise-pr plan-report test-writer github-writing binaric agent-tuneup reremember

These need only the files and tools your agent already has. On T3, agent-tuneup holds the dispatch preflight that other skills read before starting a delegate, so install it alongside them.

How skills choose delegate routes and check subscription capacity is in the workflow guide.

Aside · the research

Why another model family checks the work

Models can favour their own writing and repeat mistakes made by related models. So when review checks code, the reviewer comes from a different model family from the code's authors.

  • Self-preference

    GPT-4 and Llama 2 tended to prefer text they could recognise as their own. Another study linked GPT-4's preference to how familiar the text was.

    Panickssery, Bowman and Feng, 2024 · Wataoka, Takahashi and Ri, 2024

  • 60%

    When two models answered incorrectly, they chose the same wrong answer 60% of the time on one benchmark. A shared provider or architecture made that more likely.

    Kim et al., ICML 2025

  • Worse alone

    Models sometimes made their reasoning worse when asked to correct it without outside feedback.

    Huang et al., ICLR 2024

  • Panels win

    In one study across six datasets, a panel drawn from several model families judged more accurately and with less bias than a single GPT-4 judge.

    Verga et al., 2024

These studies tested AI judges and reasoning benchmarks, not code review. The README explains how the library applies them.

What you need

On macOS, Homebrew installs everything below. Casks (--cask) are macOS apps. On Linux, use your distribution's packages or each project's installer.

Command-line tools

brew install node python gh
  • Node.js 22.20+ runs npx skills.
  • Python 3.10+ runs bundled helpers, such as the plan-report renderer and babysitter's pr-wait.
  • GitHub CLI lets the pull request skills read checks and post. Sign in once with gh auth login.

A coding agent

brew install --cask t3-code
brew install --cask codex
brew install --cask claude-code

Install any of them. T3 Code gets the most from the library; Codex and Claude Code run every skill that doesn't need T3.

What the agent brings

Installing a skill adds instructions, not access. Reviews, browser checks and delivery use the models, tools and permissions your agent already has. UI review needs browser or device access in the host.

The paid OCR route needs the OpenCodeReview CLI with a configured provider. A public repository uses free OpenCode models instead, and falls back to that CLI only when every free reviewer fails.

To choose skills in the terminal, run npx skills add seankoji-com/.agents.
