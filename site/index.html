Install and use a skill

  1. Run the install command

    Open Install next to a skill. Run the command in your project terminal and choose agents when prompted. Tick several skills to install them together.

  2. Ask for the work

    For example, ask Use think on this plan before we build it or run /think if your agent supports slash commands.

  3. Check the result

    Your agent follows the skill's instructions and reports the outcome, with any decisions or checks still open.

Made for T3 Code

Use T3 Code to run agents from several providers in one app. Skills use T3 for separate worktrees, background tasks and pull request watches.

A second opinion from another model

review, think and challenge get a separate opinion. Written-code reviews use a different model family from the code authors. Read the rationale.

Big jobs in their own workspace

implement does the coding in a separate T3 worktree, so your main conversation stays free for decisions.

Work that carries on in the background

raise-issue files issues in a background task while your change keeps moving.

Pull request watches

babysitter uses T3's pull request watch to resume work when checks or reviews change.

Progress and designs you can see

ship, implement and review-loop use T3's Tasks row when the host exposes it. plan-report draws a timeline, and choose-design shows mockups side by side.

Using another agent

Codex, Claude Code and other agents can use skills whose required tools they provide. Look for the T3 Code requirement in the catalog.

Why another model family checks the work

Models can favour their own writing and repeat mistakes made by related models. Using another family for code review gives the change an independent check.

  • GPT-4 and Llama 2 tended to prefer text they could recognise as their own. Another study linked GPT-4's preference to how familiar the text was. Panickssery, Bowman and Feng, 2024 and Wataoka, Takahashi and Ri, 2024.

  • When two models answered incorrectly, they chose the same wrong answer 60% of the time on one benchmark. A shared provider or architecture made that more likely. Kim et al., ICML 2025.

  • Models sometimes made their reasoning worse when asked to correct it without outside feedback. Huang et al., ICLR 2024.

  • A panel drawn from several model families judged more accurately and with less bias than a single GPT-4 judge across six datasets in one study. Verga et al., 2024.

The studies tested AI judges and reasoning benchmarks. Read how the library applies those findings to code review in the repository README.
