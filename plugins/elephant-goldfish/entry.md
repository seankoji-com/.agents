# elephant-goldfish
Read `PKG/shared/learnings.md` and load this plugin's project lessons before work.

Turn an uncertain problem into a testable brief, or check a durable design document.
Read `PKG/shared/t3-runtime.md` first. Inherit the session model. Delegation follows
`PKG/shared/delegation.md`.

| Request | Load |
| --- | --- |
| `thinking <topic>` or `thinking list` | `PKG/playbooks/thinking.md` |
| `elephant [failure report]` | `PKG/playbooks/elephant.md` |
| `check` | The factual drift procedure in `PKG/playbooks/elephant.md` |
| `doctor` | Check Python 3.10+ and the state helper's `--help`; `gh` is needed only for optional publishing. |

Thinking ends at the handoff. It does not start implementation or create another thread.
Requirement changes refine the brief. Discovery review and final readiness grant no
execution authority. Preserve the thinking boundary on resume, compaction, and scheduled
continuations, including when unrelated production work was authorised in this thread.
Only a clear user instruction to leave thinking changes that scope; record the request
and its scope first. If intent is materially ambiguous, clarify before implementation.
Cold review checks whether the document is usable; factual verification checks its claims.
Keep those verdicts separate.
