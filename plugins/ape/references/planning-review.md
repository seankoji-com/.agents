# Planning review for ape

Use `python3 PKG/scripts/plan_review.py COMMAND --input FILE`. This helper stores
local metadata and validates references. T3 owns child dispatch. The shared
`PKG/shared/planning-review.md` API owns review jobs, fallback, counters and acceptance.

1. Before project investigation, fingerprinting, drafting or dispatch, collect the
   native batched work/review choice. Study needs `workhorse`; forage also needs
   `judgement`. Primary panel/coverage and finite authorised replacements are
   separate. Freeze scope with `logical_output_id(request_reference, output_name)`.
   `admit` takes `operation`, `request_reference`, `output_name`, `invocation_id`,
   `selection`, `selection_sha256`. A GitHub URL alias becomes study once. `continue`
   takes `admission`, `invocation_id`, `event` and optional `forward: true`; a second
   forward or renewed invocation using old choices fails. Raw fetch and deterministic
   doctor/clean helpers neither prompt nor gain a planning pass.
2. Keep the returned `ape_admission`, selection/digest, invocation and scope in the
   ordinary research job. Tasks bind the selected role and producing digest.
   Existing job creation/preparation rejects missing choices. Research remains
   read-only. Obtain any work replacement authority separately from review fallback.
   An explicitly chosen coordinator synthesis declares
   `resources.ape_output_type: forage-synthesis`, `execution_mode: direct` and a
   current-context `judgement` selection binding on the final stage, with no child
   slot there. Record its actual direct execution. This cannot relabel a research
   child or lower the synthesis role floor.
3. Ingest research and run citation/inspection checks. Accept forage-research before
   synthesis. Before final study/report acceptance, call `prepare` with `descriptor`,
   `job_file`, `stage_id`, absolute coordinator `metadata_file` and `inputs`.
   Inputs name verbatim `requests`, `decisions`, full stage `requirements`,
   `load_bearing_decisions`, `repository_root`, relevant `evidence_paths`, optional
   `declared_paths` and `attachments`. Request clauses follow shared capture rules.
   Bound files may carry explicit confidential `data_class` labels. Retain the
   snapshot and stable `subject_file` in report metadata outside worker subtrees.
4. Create a separate shared planning job with `plugin: ape`, the returned snapshot
   and producing selection. Its pinned manifest selects the managed synthesizer's
   read-only planning mode and local rubric. The snapshot derives actual researchers,
   synthesizer and coordinator identities from the producing job. Record adopted
   contributor prose with hash-bound `document-authors.json`; critique alone adds
   no author. A same-lineage fallback must say so. Every final conclusion, including
   empty findings/no adoption/no experiment, needs complete review coverage.
5. Use shared begin/launch/host-event/result or permitted direct observations/finish.
   Retain all objections and finite budgets. `attach` takes the original descriptor,
   metadata file and actual receipt path; it refuses adverse/stale/missing evidence.
   Put its returned `metadata` pin in the final descriptor's `planning_review`.
   Freeze that descriptor, then run ordinary `accept-stage` and `validate-final`.
   They dereference the real receipt and current source/request/rubric/criteria/
   author/producing-choice bindings. Intermediate source reports need no duplicate
   final pass. Do not review generated metadata or receipts as their own inputs.

`validate` takes `{descriptor}` and returns actual modes, panel/degradation, rounds,
findings/dispositions, stable subject and HEAD observation. Unrelated HEAD movement
alone preserves the producing pass; bound evidence drift needs review. Automatic
wakes/repairs retain choices and counters. A new command collects choices; unchanged
accepted bytes keep their producing evidence. Explicit re-review consumes the retained
budget. Deliver requested outcome, actual selected/observed models and substitutions,
reviewed scope, feedback changes, retained objections/limits and next action. Planning
acceptance grants no implementation, experiment, settings or publication authority.
