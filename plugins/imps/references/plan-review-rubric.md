# IMPS planning and conclusion review

Apply `PKG/shared/agents/reviewer-standard.md` and the frozen request, decisions,
requirements and load-bearing decisions. Review the declared integrated output,
including zero findings, no risk and no change. Give every requirement an outcome,
evidence, strongest contrary case and coverage limits. Retain every prior objection.

For audit, distinguish confirmed defects, hypotheses, mitigations, refutations and
uninspected dimensions. Challenge the recommended fix order and checks. Investigation
must compare competing explanations; a source citation alone does not prove a causal
claim. Blast-radius must trace actual consumers, persisted formats, recovery paths
and cleared edges at the reviewed snapshot. An empty report still needs coverage.

For an initial gate plan, check the exact effective requirements, repository policy,
checks, write actions, stage dependencies, integration and observable acceptance.
Review before execution if any write, multiple stages or synthesis is planned.
Read-only single-stage literal checks add no initial planning assessment.

For verification recipes, inspect authored launch/readiness, feature selection,
drive/observe, isolation, timeouts, process ownership, cleanup and failure recovery.
Test the strongest omitted path. Scaffold/check and later runtime success do not
establish the adequacy of these decisions. No production credentials or real sends.

Planning review never grants execution authority, permits a fix during an audit,
changes requirements or replaces later code or persona review. Engineering review
keeps its adverse-is-final rule. Planning disputes use the separate shared contract.
